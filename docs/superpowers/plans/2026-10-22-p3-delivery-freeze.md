# P3 项目交付与版本冻结计划

**依据：**用户确认的 P3 专家方案；仅在现有仓库执行。**起点：**`919f4fb`，分支 `codex/refund-hil-p0`。

## 范围

只整理文档、证据、演示和学习路线；不修改 Agent 业务源码、配置或原始评测，不运行 40 条付费场景，不启动新功能。保护原有 `docker-compose.yml`、`.dockerignore`、`.serena/`。不推送、不清库。

## Task 1 — 版本与事实盘点

核对 Git 状态、提交与上游基线、Compose 实际工作区差异；读取 P0/P1/P2/P2.1 报告和关键源码符号。仅输出不含密钥的功能矩阵、复现前提与贡献归属。不得把 `origin/master..HEAD` 自动等同于全部个人贡献。

**验收：**来源路径可追溯；当前环境与干净构建分开；未更改业务状态。

## Task 2 — README 与演示说明

精简 README，区分已验证、代码可选、未验证功能；包含整体 Mermaid 架构图与退款 HIL 时序图。新增简明演示说明：只读订单、知识/多轮、退款申请确认流程，附 API 形状、环境前提、源码位置和已有证据；敏感字段一律占位。说明 PostgreSQL 与 MySQL 职责、Compose profile、源码只读挂载和干净构建限制。

**验收：**链接存在、Mermaid 语法可读、命令与实际配置一致、不出现真实密钥；演示写操作仅使用全新合成订单。

## Task 3 — 贡献、验收摘要与学习导航

从 Git 提交和 P0/P1/P2/P2.1 报告做“原问题→函数/文件→修改→证据→追问”表；形成六部分中文源码学习导航，每部分约五个追问。汇总测试和评测口径，列三个实际 Bug/Bad Case 与未完成风险。不把原仓库既有设计据为己有。

**验收：**所有数字与原报告一致；40 例网络/JWT/Mock分母和人工裁定清晰；不编造生产指标。

## Task 4 — 轻量验证与本地封版

只做现有容器及关键接口的轻量只读 smoke，复核文档链接、秘密扫描、Git diff、现有自动测试；干净 Docker Build 仅检查条件，若耗时或会破坏环境则记录未验证。只提交本轮归属明确的文档，不暂存用户原有未提交内容，不推送。记录最终 SHA 与工作区状态，随后停止功能开发。

**验收：**报告清楚列出通过、失败、跳过及局限；最终提交可回查，用户改动原封保留。
